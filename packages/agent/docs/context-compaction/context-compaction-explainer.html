SA-1948 — Conversation Compaction Explainer

When does it summarize, what does it keep, and why a given config may never compact. Config lives in the sticky left column — change it and the results on the right update live.

1. Three knobs — don't mix up their roles

VariableRole
CONTEXT_MAX_TOTAL_TOKENSWHEN to consider compacting. Compaction is only attempted when total_tokens > MAX_TOTAL_TOKENS × THRESHOLD (the gate).
CONTEXT_COMPACTION_THRESHOLDGate ratio (default 0.80 = 80%). Together with the above it forms the gate.
CONTEXT_MAX_MESSAGE_HISTORYHOW MANY recent turns to keep verbatim. Only turns OLDER than this are summarized ⇒ you need more turns than this before anything can be summarized.
CONTEXT_AGGRESSIVE_THRESHOLD
CONTEXT_DANGER_THRESHOLD		Which strategy to apply, based on pressure = total_tokens / MAX_TOTAL_TOKENS (see section 2).

👉 MAX_TOTAL_TOKENS = WHEN. MAX_MESSAGE_HISTORY = HOW MANY to keep. AGGRESSIVE/DANGER = HOW to handle it.

2. Decision flow (runs every chat turn)

  1. Count total_tokens of the whole history.
  2. If total ≤ gate → NO compaction
  3. If over the gate → compute pressure = total / MAX_TOTAL_TOKENS, then pick the band:
Pressure bandActionProduces [Conversation summary]?
THRESHOLD → AGGRESSIVE e.g. 0.80→0.85tool_result_clear❌ no-op for role "user" messages
AGGRESSIVE → DANGER e.g. 0.85→0.95SUMMARIZE (LLM)✅ only when turns > MAX_MESSAGE_HISTORY
≥ DANGER e.g. ≥0.95head/tail (drop middle)❌ just trims, does NOT call the LLM

The code only writes the DB when a [Conversation summary] is produced. Landing in tool-clear / head-tail → nothing is written → the history never shrinks (it keeps growing).

3. Conditions to ACTUALLY summarize (all 3 required)

①total_tokens > MAX_TOTAL_TOKENS × THRESHOLD (over the gate)
②AGGRESSIVE ≤ pressure < DANGER (inside the summarize band)
③turns > MAX_MESSAGE_HISTORY (there are turns older than the kept tail)

5. Takeaway on a too-small budget

Example broken config: MAX_TOTAL_TOKENS=100, DANGER=0.95, keep=10.

  • A real conversation ~300 tokens → pressure ≈ 3.0 → ≥ DANGER 0.95 → always lands in head/tail → never summarizes.
  • The summarize band is only 85–95 tokens — smaller than a single real message → the history jumps straight past it into the danger zone.

To make it compact (try the "③ FIX" scenario): raise DANGER=10 and lower AGGRESSIVE=0.80; to compact from turn 2, also set keep=1. For production: pick a model in the dropdown so MAX_TOTAL_TOKENS ≈ the model window and keep danger 0.95.

6. Suggested MAX_TOTAL_TOKENS per model 🤖

MAX_TOTAL_TOKENS is the token budget for the CONVERSATION HISTORY replayed to the model each turn. Set it below the context window to leave room for the system prompt + tools + the reply. Rule of thumb: ≈ 50–70% of the context window. Keep 0.80/0.85/0.95.

⚠️ Context-window sizes vary by version & provider — verify against the actual model & API you use before committing. These are reference figures only. Use the dropdown in section 4 to load them quickly.
