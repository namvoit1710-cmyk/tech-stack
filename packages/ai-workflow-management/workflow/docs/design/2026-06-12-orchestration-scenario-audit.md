# Orchestration Scenario Audit — fan-out × sub-workflow × revisit × pending

**Date:** 2026-06-12
**Scope:** workflow-control-plane-service orchestration engine, branch `feature/workflow/SA-846-cycle-execution`
**Method:** live queue-driven probes (`tests/integration/test_orchestration_scenario_audit.py`, 7 scenarios, all green as behavior pins) + existing suite runs + code trace of `_route_to_successors`, `ChildWorkflowCoordinator`, `MergeNodeHandler`.

## Verdict

The core architecture is **sound for the happy paths** — nested sub-workflows (depth 3+ with correct `depth_level`/`root_run_id` lineage), parallel fan-out into multiple sub-workflows, and pending INPUT inside a child (pause → resume → child completion cascading to the parent under the reentrant child→parent lock) all work end-to-end. It is **not yet satisfying for revisit semantics at convergence points**: the engine cannot distinguish "cycle re-entry" (re-run wanted) from "late fan-in arrival" (re-run NOT wanted), and the in-flight coalesce window silently drops legitimate revisits.

## Verified working (probes 1–4, 6; existing suites)

| Scenario | Result |
|---|---|
| Sub-workflow in sub-workflow (depth 3) | parent/child/grandchild all COMPLETED; depth 1/2, root lineage stamped |
| Fan-out → two parallel sub-workflows | both children COMPLETED, parent COMPLETED |
| Pending INPUT inside child | child PENDING, parent RUNNING; one resume cascades child → parent → successor |
| 2nd edge into PENDING INPUT | coalesced into the existing pending task, exactly 1 InputRequested, resume completes run |
| WORKFLOW-node revisit after child completed (Mode B) | fresh child run per arrival (visit-keyed child-run id) — fixed 2026-06-11 |
| MERGE all/any/n_of_m at equal branch depth | fires at correct count, downstream once |

## Confirmed gaps

1. **MERGE quorum revisit double-fires downstream** (probe 5) — **FIXED 2026-06-12**. With `n_of_m` (n=2) and an uneven third branch, the late arrival re-entered the satisfied MERGE → merge `-v1` task → `final` executed **twice**. Fix: a `__fired__` sentinel inside the scope's quorum buffer (persists/resets/scopes with the buffer — loop iterations and test-run resets re-arm naturally); post-fire arrivals are recorded but return the new `"absorbed"` completion mode, which terminates the straggler task quietly (COMPLETED, no routing, no events — `deferred` would leave it READY and stall quiescence). Executor-mode parity in `executor_consumer` (mark terminal, skip `NodeOutputProduced` so the Dispatcher doesn't tee `EdgeTraversed`). Probe 5 now asserts at-most-once; +5 unit tests. Deliberate cycle re-arm (clear sentinel on loop re-entry) remains the open SA-846 design item.
2. **Mode A in-flight coalesce drops revisits** (probe 7) — **FIXED 2026-06-12**. A WORKFLOW node's tracking task stays RUNNING for the whole child duration (window scales with child depth), and any second arrival in that window was silently dropped. Fix: deferred revisits. `RunContext.pending_revisits` (persisted in the HANA context JSON) records an arrival that lands while the node's task has *started* (RUNNING/PENDING/WAITING/RETRYING — READY tasks still absorb losslessly, preserving plain diamond-join behavior); `check_run_completion` drains it once the node quiesces (un-skip + visit bump + fresh `-v{n}` task) and the dispatch makes the run non-quiescent, so a run can never complete with a queued revisit. Set semantics: one re-run per window no matter how many arrivals landed in it. Loop-scoped arrivals keep the legacy coalesce (a revisit task carries no scope_stack). Applies uniformly: WORKFLOW nodes re-spawn a fresh child (the former strict-xfail repro now passes), pending INPUT re-requests after resume, nested child trees re-execute whole. Cleared on test-run reset alongside the merge quorum buffers. Revisit timing is now deterministic instead of queue-interleaving-dependent.
3. **Loop body with CONDITION stalls** — **FIXED 2026-06-12**. `is_iteration_done`'s body BFS required *every* body-subgraph node in `iter_progress`, including nodes on the branch the CONDITION didn't take (cascade-skip used to mark them skipped; its retirement removed that accounting). Fix: the BFS is now routing-aware — CONDITION/SWITCH/gated-PARALLEL nodes expand only along their `last_taken_edge_ports` mirror entry (freshly overwritten each iteration), so untaken-branch nodes are not required. Missing mirror entry falls back to all edges (conservative: a stall is recoverable, premature iteration-advance corrupts loop state). +3 unit tests; all loop suites green.
4. **~32 child-workflow integration tests are dead weight** — **PORTED 2026-06-12**. Two files held all 32 after the publish fix: `test_child_workflow_human_action.py` (21) and `test_child_workflow_input_event_order.py` (11). Port pattern: deps fixture wires `MemoryOrchestrationQueue` + `engine.set_queue`, a `_drain_queue` helper drives the **production `OrchestrationWorker._dispatch`** after every use-case call, and the event-log → `CachedProjectorRunContextViewStore` chain is wired (node outputs are view-only since Phase 3b.1 — resolution of `{{$node.field}}` silently broke without it). The port surfaced **two real regressions** (fixed, see below) plus contract drift that was updated: skip-bookkeeping assertions → "never ran" (cascade-skip retired), legacy topics (`inputrequested` → `input.requested`, `run.completed` → `run.status`+status), lane-priority ordering → causal per-node ordering, and the WORKFLOW node's `node.dispatched` now lands after `child_run.started` (the handoff boundary is `node.input`). Also repaired + ported `test_input_node_run_through.py` (stale L1→L2 import, undrained queue, view-only reads).
   - **Real regression #1 — reject re-fires the confirm branch.** `process_successors` passed no port filter to `compute_fanout` for resumed PENDING nodes (they're not in `_PORT_ROUTED_TYPES`), so a rejected HUMAN_ACTION fan-out traversed ALL edges; pre-SA-846 the skipped-nodes filter masked it, post-SA-846 the un-skip semantics re-dispatched the confirm successor as a `-v1` revisit. Fixed: the recorded `last_output_ports` (confirm/reject, set by the resume use case) now feeds `expected_port_override`, reproducing the resume-time edge classification exactly (opposite ports filtered, port-less edges continue).
   - **Real regression #2 — INPUT `runThrough` was dead.** The node schema still declares `runThrough: boolean`, but no handler read it (lost in the handler-ABC refactor) — a run-through INPUT paused anyway. Restored in `PendingHandlerBase.handle`: auto-submit the resolved prefill (task COMPLETED, `immediate` mode, prefill as node output) while still emitting `InputRequested`.
5. **Publish-rule inconsistency for children** — **FIXED 2026-06-12** (two defects, not one):
   - The production (HANA) contract for `get_by_latest_publish_version` is "latest PUBLISHED, else latest DRAFT, keyed on the logical id" — but the **memory repo** implemented strict-PUBLISHED keyed on `workflow_id` only. That divergence was the actual cause of the 41-test "Workflow not found" cluster (DRAFT fixtures with defaulted `workflow_id`). The memory repo now mirrors HANA (published-preferred, draft fallback, matches `id` or `workflow_id`, newest `updated_at` wins with version tie-break). 9 of the 41 stale child-wf tests and the 4 broken publish-endpoint tests recovered immediately.
   - `ChildWorkflowCoordinator.start` now resolves the child via `aget_by_latest_publish_version` instead of plain `aget_by_id` — sub-workflows follow the same governance as `POST /runs`: a WORKFLOW node referencing a logical child id executes the latest PUBLISHED version even when a newer DRAFT exists (probe 8 pins this; under the old resolution that graph failed outright because no row matched the raw id). Draft-only children still run, via the same fallback top-level runs get.
   - Also repaired `test_get_latest_publish_workflow.py` (referenced nonexistent `WorkflowStatus.PUBLIC`, int versions vs string DTO, and asserted strict-404 for draft-only against the HANA fallback contract).
6. **`test_input_node_run_through.py` fails collection** — ~~stale `app.layer1_domain.services` import~~ FIXED 2026-06-12 (import path + queue-driven port + view-store wiring; see item 4).
